# spec-guard

ตัวตรวจ 3 กลุ่มจาก SPEC-POS-001 (world8/backend/docs/personal-spec.md §17-19) — JSON in / JSON out, ไม่มี dependency ภายนอก, ไม่มี network, ไม่เขียนไฟล์

> [!tip] PowerShell กิน quote
> ใน PowerShell ให้ใช้ shorthand แทน JSON: `python scripts/run.py check C:/path/to/project --today 2026-10-27`
> หรือส่ง JSON ผ่าน stdin — engine รับได้ทั้ง 3 ทาง

## ใช้

```bash
# ตรวจทั้ง 3 กลุ่ม (exit 0 = ผ่าน, 1 = มีข้อไม่ผ่าน, 2 = ใช้ผิด)
python scripts/run.py '{"op":"check","target":"C:/path/to/project"}'

# ตรวจเฉพาะกลุ่ม / กำหนดวันเอง (เพื่อให้ผลซ้ำได้)
python scripts/run.py '{"op":"layout","target":"."}'
python scripts/run.py '{"op":"scope","target":"."}'
python scripts/run.py '{"op":"abandon","target":".","today":"2026-10-27"}'

# ผ่าน stdin
echo '{"op":"check","target":"."}' | python scripts/run.py
```

## ตรวจอะไร

| กลุ่ม | ID | กติกา |
| --- | --- | --- |
| LAYOUT | Y1 | มี `backend/` + `frontend/` แยก (ถ้ามีทั้ง Python และ UI) |
| LAYOUT | Y2 | มี 4 แกน: `skills/` · `tools/` · `data/knowledge/` · `data/store/` |
| LAYOUT | Y3 | `.gitignore` ครอบ `data/store`, `generated`, `node_modules`, `.venv` |
| LAYOUT | Y7 | มี `docs/` + gate script ของโปรเจกต์ (check.py ที่รันซ้ำได้) |
| SCOPE | B2 | generated bytes ≤ 50% ของ repo |
| SCOPE | B3 | authored files ÷ capability (tools/*.py) ≤ 3 |
| ABANDON | X1 | docs ≥ 10 หรือ span ≥ 3 วัน (day-0 ไม่ตัดสิน) |
| ABANDON | X2 | ถ้า idle > 14 วัน ต้องมี `ARCHIVE.md` (พิธีฝังศพ B5) |

## กติกาการใช้

1. `[FAIL]` ไม่ได้แปลว่างานเสีย — แปลว่า "ยังไม่ตรงโครง" และตัวเลขคือหลักฐานที่ต้องอ้าง
2. **ห้ามปิดข้อที่ไม่ผ่านด้วยการเพิ่ม ignore** — แก้ที่การย้ายไฟล์/แยกโฟลเดอร์
3. `X2` เป็นการเตือนให้ทำพิธีฝังศพก่อนเปิดโปรเจกต์ใหม่ ไม่ใช่คำสั่งให้ลบ
4. `state` (active/dormant/dead) คำนวณจาก mtime — เป็น proxy ไม่ใช่คำประกาศ abandon

## ข้อจำกัดที่รู้ตัว

- ไม่ตรวจ semantic ของ import ข้ามชั้น (กติกา Y6) — ตรวจได้แค่ว่าโฟลเดอร์มีจริง
- `B3` นับ capability จากจำนวนไฟล์ `.py` ใน `tools/` — โปรเจกต์ที่ไม่แยก tools จะถูกข้าม
- ไม่มี `--fix` โดยเจตนา: การย้ายไฟล์ต้องมีการตัดสินของเจ้าของ
